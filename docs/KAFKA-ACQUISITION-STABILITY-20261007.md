## Follow-up: exact-byte executable reuse

After committing the five-client RED, the generic `CapabilityExecutableSnapshotPool` reuses one immutable private executable incarnation. Its limits are four entries, 256 MiB retained private storage and a fixed thirty-second reuse window. A single expiry timer releases idle pool ownership; active contracts retain their own private bytes. Every acquisition reads/hashes the full current source before reuse and again before return. Exact source permissions/withdrawal are checked, return races fail closed, and a failed old return cannot evict a concurrently acquired new incarnation. Neither file metadata nor timestamps stand in for source identity. The private snapshot size is used only for byte-budget accounting. Credentials, signer keys, policy, metadata and broker responses are not pooled. Current full source-byte and metadata checks at dispatch remain in place. The normal user receives no new knob, integration or AI operation.
