# Direct Linux D-Bus runtime pressure test

The Linux runtime now automatically reads the standard `DBUS_SESSION_BUS_ADDRESS`, enumerates currently owned names, and walks declared child nodes using the documented D-Bus introspection interface. The resolver compiles acquired methods into the existing `CapabilityInterfaceReflector`, RCIR admission, policy, lifecycle, verification and signed-receipt host. It adds no AI operations or second execution engine. The normal discovery path requires no per-provider artifact configuration or adapter enablement.

The native client is the host's `/usr/bin/busctl` by default. Its executable is captured in a private immutable snapshot, calls use bounded arguments/JSON, option parsing ends before provider values, and service activation is disabled. Discovery is bounded to 32 names, 64 nodes and depth eight. A four-second deadline is checked between acquisition steps; individually bounded resolver calls can make total wall time exceed four seconds. Missing session/client/parser support abstains. Linux distribution dependency/clean-install acceptance remains an outstanding release gate.

Each acquired contract binds the exact XML, bus `GetId`, unique owner, Unix owner UID, native signatures and argument order. Discovery and the final common admission gate recheck those identities. Dispatch addresses the acquired unique owner. A well-known name release invalidates the old declaration even while its original connection remains callable. A restarted bus cannot reuse an old binding merely by allocating the same unique owner name.

Supported native types are exactly strings, Booleans and bounded arrays of those types. Non-string Core inputs use the existing bounded, type-tagged CapabilityValue wire JSON; strings stay literal. The descriptor compiler opts into this compatibility adapter. Existing string-only consumers and other compilers keep their previous encoding. Zero-output native method returns use the existing explicit RCIR unit/completedWithoutOutput boundary, remain accepted/unverified without observation, and supply no typed provider output.

D-Bus introspection does not declare application read/write side effects. The RCIR scope permits execution of one exact native member; it does not infer side effects from the member name. Unknown safety continues to require confirmation. Fine-grained application effect declarations remain RED.

An optional trusted-host binding names a declared string argument reserved for the host invocation marker. The complete native signature and selected binding remain in the contract; the reserved field is absent from model arguments and substitution is rejected. The existing BoundInvocation seam injects the admitted task identity. This is optional engineering/host composition, not a requirement for ordinary discovery or safe typed read methods. Without an independent stored marker, observation establishes only a state predicate. The acceptance observer never echoes its request header as proof.

## Evidence and limits

`evidence/linux-dbus-20261007` preserves raw declarations, transcripts, effects, observations, policy, trusted public keys, receipts, test/build attempts and a hash manifest. Native targeted tests: 13 passed, zero skipped. Shared/native Linux regression: 97 executed, 95 passed, two existing unprovisioned WASM skips. macOS shared compiler/type/process regression: 51 executed, 49 passed, the same two WASM skips. The final native proof includes an independent UID1101 file digest and read-only D-Bus read, a UID1100 writer, UID1102 service owner, separately pinned OpenSSL signature verification and the independent Python receipt decoder. The stable mounted self-use runtime remains 0.2.2 with its own attested binary hash; it is not the native candidate binary.

This is a scoped direct Linux unary-method GREEN. It is not full Linux, Windows, G1/G3/G6/G9, the eleven-substrate matrix, fresh AI acceptance or released/distributed GREEN. Numeric widths, binary/handles, variants, dictionaries, structs, properties, signals, ObjectManager/event subscriptions and NoReply methods remain unsupported/RED rather than becoming strings. Name lifecycle here is checked on acquisition/final admission; a reactive universal event cursor remains separate outstanding work. Production issuer/delegation and signing-key lifecycle, native distribution and clean install, integrated CI and the final restricted-agent proof remain outstanding. The native CI workflow is provided, but only a completed run can establish its result.
