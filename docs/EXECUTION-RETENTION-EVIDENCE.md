Defaults are 1,024 records, 16,777,216 encoded/reserved bytes and 300 seconds of terminal history. Byte bounds describe the encoded record accounting, not a promise that process heap allocation is exactly 16 MiB. Active task summaries have byte allowances reserved before dispatch. Active ownership is bounded by count and byte capacity, and the existing task owner remains responsible for terminal callbacks/deadlines; history expiry does not cancel external work.

Terminal expiry starts when the stored task first becomes terminal. Reads and terminal updates do not extend it. The clock uses monotonic uptime and clamps regression; eviction order is insertion order among terminal records and does not depend on dictionary enumeration. First-put confirmation-denied `awaiting_user` records have no started reservation and expire normally. `put` and `update` return false when storage/reservation cannot be admitted; engines must check initial reservation before dispatch. Expired/evicted records return nil; the seven-operation engine must report unknown and must not invent historical evidence.

Oversized records are compacted into explicitly labelled in-memory status summaries. The summary cannot independently verify an outcome and does not carry an executable receipt signature. A digest of discarded payload is only an identity aid. Provider execution returns its original full first record to the caller; retaining history does not mutate that record. There is no automatic durable receipt export in this change.
