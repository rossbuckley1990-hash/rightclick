# One product, one runtime

This is an engineering acceptance record for the amended objective, not an
announcement of an accepted portable release. The primary product stays
`rightclick`; clients, plugin channels and protocols consume the same core.

The normal journey is install → start/connect → discover → perform a real
action. RCIR, admission, authority, policy, tasks, verification and receipts
belong beneath that journey. Provider acquisition must not require a new AI
tool or a separate RIGHTCLICK process per substrate.

| Architectural increment | Install impact | User concept | Internal boundary | New integration learning | Automatic discovery | Minutes to real success |
|---|---|---|---|---|---|---|
| Shared native host files and HTTP/process fixes | Existing package gains a small native helper; one executable | None | Host backend and bounded transports | None | Preserves existing discovery | Native first-use timing still RED |
| Typed unit completion and inherited OpenAPI authority | Existing package | None | Compiler/RCIR and protected credential references | None | Supported declarations compile normally | ACK acceptance is useful, but semantic proof needs an independent outcome contract |
| Internal authority attenuation | Existing package | No public delegation operation yet | Shared admission ledger and trusted caller context | None | Does not change acquisition | Production identity/broker setup remains RED |
| Invocation-bound independent verification | Existing package | Normal goal/outcome; operator may provision a verification contract | Shared host observation boundary | None | Uses declared capabilities; provider metadata cannot choose trust | Fully automatic verification contracts remain RED |
| Versioned Core-profile advertisement | Existing package | None for existing consumers | Runtime identity advertises the canonical seven operations | None | Existing clients keep discovery | Actual first-effect proof remains separate from identity/catalogue checks |
| Native Linux D-Bus acquisition in progress | Same executable; existing host bus utility | None on a normal session | Native discovery/compiler/transport beneath common RCIR | None | Intended standard session-bus discovery without service activation | Genuine native discovery/execution and measured timing still RED |

Current diagnostic provider descriptors and explicit host credential/observer
references are controlled proof inputs. Their existence is not evidence that a
new user must manually wire every provider. The final product must establish
safe defaults and secure discovery, credential acquisition and outcome contracts
without exposing secrets to the agent.

The existing Mac Stable installation and its local-client setup commands remain
the baseline. Linux/Windows onboarding, secure OS credential integration, useful
empty-configuration behavior on all hosts, and clean installed first-action
timings must be measured on released bytes before this gate can become GREEN.
