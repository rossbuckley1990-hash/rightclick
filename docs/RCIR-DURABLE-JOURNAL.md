# Durable invocation identity, first protected backend

This slice adds an operator-selected journal to the existing RCIR execution host. It does not add a task engine, adapter dispatcher or AI operation. macOS/Linux use the protected POSIX backend. Without explicit configuration, execution retains the existing volatile history and says so. Windows retains volatile execution and explicitly reports that durability is unsupported; an explicit durable configuration fails closed there.

Set `RIGHTCLICK_INVOCATION_JOURNAL` in the trusted runtime host environment to an absolute native physical directory path. Its parent must exist. The journal creates the selected directory with mode 0700; an existing directory must be owned by the runtime user and private. All path components are opened without following symlinks. Files must be owned regular 0600 single-link files. Extended Darwin ACLs are refused. For example, `/private/tmp/...` is the native physical spelling on macOS; Foundation's normalized `/tmp/...` spelling traverses a symlink and is rejected. Provider metadata and AI arguments cannot select this location.

The shared dispatch path persists an intent before final lease consumption/enqueue, outside the admission lock. It then checks the live graph, current typed contract, authority, policy and signer reference again. Journal failure before dispatch prevents the provider start. If a later checkpoint fails after an effect or independently known outcome, the live evidence is preserved and the earlier durable intent remains uncertain on restart.

A closed schema retains execution/task/lease UUIDs, generation, request and binding SHA256 commitments, closed effect names, timing, phase, sequence, outcome/status, and optional receipt SHA256. It cannot receive raw arguments, credentials, resource identifiers, outputs, observations, events, authority grants, callback handles, or signed receipt payloads. A checksum detects accidental corruption; it is not protection against an attacker operating as the same OS principal.

`context_run_status` first uses the current execution session and volatile evidence, then the journal. An unfinished retained invocation becomes UNKNOWN without reconstructing authority, replaying a mutation, polling a remote provider or asserting zero effects. A completed historical success without its archived receipt and independent evidence is returned as accepted and unverified, with the prior durable state labelled as historical. The journal does not establish a new verified-success claim.

Transactions reload under a nonblocking named writer lock, use a single bounded private staging snapshot, fsync it, atomically rename it, and fsync the directory. The lock pathname must still identify the pinned single-link inode after locking, before commit and after commit. A persistent initialized marker distinguishes a new store from a missing committed snapshot; a live handle also pins the marker inode and rejects marker replacement or removal, including loss of both files. A nonempty snapshot with no marker rejects on reopen. A fresh process cannot detect a same-principal deletion of the entire initialized directory/history; this backend is not an authenticated archive against its owner.

Defaults bound the active snapshot to 2 MiB and 1,024 entries. One fixed staging file bounds interrupted writes to one additional snapshot; protected abandoned staging files are removed under the writer lock. Known terminal summaries expire after seven days or can be evicted for capacity. UNKNOWN/outcome-unknown identities remain pinned, including terminal UNKNOWN mutations. A full store with only unresolved identities denies new dispatches; it never deletes uncertainty to admit another effect. Operator recovery/reset is a later gate and is not an automatic retry path.

## Evidence and remaining gates

The frozen real-process acceptance script is `scripts/acceptance-rcir-restart.py`, commit `db26a99`, SHA256 `9328eccdd043711308beaefad1ee98252bf7a1f6f8f1c7df42e1c96e2621e5dd`. It uses only the seven public RIGHTCLICK operations against an isolated local A2A provider, independently witnesses one nonce-bound external effect, kills RIGHTCLICK with SIGKILL before polling, and restarts the same executable. Exact baseline source `2dd7bd2fafbbaa994812d1bc904730b74aa74816` with binary SHA256 `80f5e7875f84deaeeeb04ced3f5d2d7137ad046a0a8af8a91887532253f1100a` loses the identity on restart (RED). Evidence is retained under `evidence/rcir-durable-journal-20261007/red/`. The earlier setup error is retained separately and is not the functional RED.

Native tests exercise private storage, symlinks/hardlinks/ACLs, integrity/coherent states, lock replacement/contention, initialized history loss, staging cleanup, bounded retention, post-intent drift, identity substitution and checkpoint failure. Test results and the unchanged acceptance script's final GREEN are bound to exact source/binary in the companion evidence manifest. These are engineering controls and a scoped crash proof, not an eleven-world restricted-agent result.

The following remain required programme gates: automatic/default production durability with validated path/key/retention behavior on every host; a native Windows durable backend; signed receipt/evidence archival and key lifecycle/trust distribution; explicit supervised uncertain-effect reconciliation; recovery discovery when the caller never received its execution ID; async/stream reconnection and checkpoint resumption without reconstructed authority; power-loss proof; convergence of every substrate route into the shared host; the full eleven-world experiment; immutable release, package/bottle alignment and clean-install serving-runtime verification. No main merge, release or tap update is performed by this slice.
