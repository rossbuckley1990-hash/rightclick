## Remaining limitations and manual actions

No external/account action blocks this v0.1 release. Repository, tag, assets, tap, bottle and actual public installation are complete. Ross does not need paid Apple membership. Developer ID, notarisation, signed standalone installers and their Gatekeeper acceptance are **DEFERRED UNTIL USER DEMAND JUSTIFIES PAID APPLE DISTRIBUTION**; their scripts remain available.

Runtime targets Apple Silicon/macOS 14+, but independent installed acceptance covers macOS 26.4.1 and CI covers macOS 26. Older macOS versions have not been independently validated; they need compatible free tools with Swift 6.2+ for source fallback. A new-machine test remains useful portability evidence, not a claimed result.

Installed provider metadata and safety classifications require judgement; a returned-text contract is not proof that a provider is harmless. Confirm sensitive operations and trust the installed software. Not every app exposes a compatible contract. Finder Action extensions are discovery-only; interactive actions may require a person. Execution records are process-local and do not survive restart. There is no universal external outcome verifier.

Homebrew uninstall was exercised before the fresh public install. It removes the keg and command, while user configuration/logs/token are retained deliberately. RIGHTCLICK is left installed and Cursor is connected to it. Social launch posts have not been sent; publication authorisation covered the repository, release and tap.

## Release sequence and thesis

The completed sequence was: full suite/release build → deterministic source asset → authorised source main and immutable tag → GitHub Release source/checksum assets → public-byte verification → pinned public tap → reviewed Homebrew CI build/test/bottle → standard pr-pull bottle publication → public source-build acceptance → uninstall/untap → exact public bottle install → installed CLI/setup/protocol/Cursor/BBEdit acceptance → publish final evidence and release notes. Repeat the preparation and acceptance gates for a new version; never replace the v0.1.0 source or tag.

The evidence strengthens the technical Capability Reflection thesis: an ordinary app installation added capabilities with no bespoke integration, and a generic executor produced an independently verified useful result. Yojam independently strengthens acquisition evidence while weakening any claim of uniformly reliable semantic execution. Company demand, cross-app breadth and repeat usage remain hypotheses. v0.1 is ready to test whether users discover capabilities from untested apps and value avoiding bespoke integration setup.
